# UI-04 — uniform build grid and responsive composition

Implemented and verified locally September 10, 2026. UI-04 only; UI-05 was subsequently completed; see [final fixes and acceptance](UI-05.md). Measurements below are historical UI-04 evidence. No mockups, visual variations or publishing.

Build tools now have code-native SVG symbols, visible labels, live prices (including finite tutorial Free offers), a cyan selected state, and dashed, labeled, natively disabled tutorial locks. Unaffordable tools retain the existing selectable behavior so players can inspect them; underlined warm-colored prices and explicit cost/funds feedback explain the constraint. Selection does not waive a charge. Removal remains Clear on the compact card, with the existing accessible Remove name and actual-payment refund behavior.

All shelves use four equal columns, including the three-service shelf, so category switching does not change tool geometry. At the representative desktop size all categories appear in two columns of shelves at bottom-right; each tool is approximately 113×68 CSS pixels. The grid responds to the allocated build-region width using container queries. Narrow screens show three category tabs and one shelf below the mission, with approximately 89×68 tools. Labels/prices remain 17.6px and controls meet the 44px interaction minimum. Rotate occupies a dedicated readable row and shows the entrance direction; desktop retains the R cue. Category positions remain stable when rotation appears.

The shell no longer overrides palette geometry. Its measured map rectangle and existing camera integration remain authoritative. Narrow rotation may reserve 53% of the frame for the dock, with tighter palette gaps; longer mission copy and Details scroll within their allocation while progress and actions remain visible. This pass fixed clipped mission actions under a waiver notice and a Details overlap exposed by the composition changes. The mission and persistent controls remain outside map input. MapControls, direct Debug access, guidance handlers, model, save and camera code were inspected and preserved without changes.

## Limits and reusable finding

The narrow selected-tutorial map is shallow (102px high), though actual touch placement and subsequent road drawing pass. Long instruction/waiver text and secondary Details require scrolling; this is not physical-phone comfort testing. No physical iOS/Android, screen-reader session, nonzero hardware safe-area, RUN host lifecycle, or full fresh tutorial arc is claimed. UI-05 remains the separate whole-interface acceptance task.

A component grid must use its allocated width, not the browser width: a desktop bottom-right region can be too narrow for three shelves even when the window is wide. Test mission Details and free-price notices alongside rotation; fixed-height tool rows can otherwise expose clipping or overlapping task actions that ordinary initial-state bounds miss.
