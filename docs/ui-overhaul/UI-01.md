# UI-01: gameplay shell

Implementation: local, September 10, 2026. Only UI-01 is implemented. UI-02 through UI-05 remain separate work; nothing was published.

React now allocates a top bar, a center map region with camera/status controls, and a bottom dock. Desktop places the existing objective/jobs on the left and construction on the right. Narrow frames stack mission above construction. Automatic mode uses the available width for short landscape at widths of at least 760px; explicit portrait preference is unchanged. Short landscape uses two dock columns; its guidance moves into the build region so it cannot consume the entire mission region. Long existing cards and tool lists scroll inside their allocations.

The existing diagnostic controls remain in the desktop header. Narrow frames expose the same controls through Views in the camera toolbar. Opening Views reserves a bounded row. Vehicle Debug reserves a column beside the map and scrolls its own content. City report, jobs, expansion, manager and pause dialogs retain their existing modal behavior; the future Dashboard redesign is UI-02.

`useFrameSize` measures both dimensions of the actual app frame. Shared shell spacing uses 4/8/12/16/24px, with 44px controls and 17.6px shell text. Existing component-specific presentation is retained, with layout overrides where the smaller allocated width requires wrapping or scrolling. Safe-area side/bottom padding remains supported.

Pixi derives its viewport, mask, canvas CSS clip and input hit area from the single `.city-map-viewport` rectangle relative to the canvas. Resizing or opening panels retains world focus and zoom. A geometry change cancels an in-progress stroke, preventing a road from joining old and new pointer positions. The canvas has an explicit compositing layer clipped to that rectangle; full-screen screenshot inspection found that the scrollable dock could otherwise paint a blank strip across the map despite disjoint DOM bounds. Crop-only screenshot comparisons missed this, so the regression compares map pixels extracted from full-game screenshots with the dock visible and hidden.

## Remaining limits

This is the shell foundation, not the finished visual overhaul. At 320×640 and in short landscape, long mission text/actions, extra build categories and secondary diagnostics require scrolling inside their regions. The existing mission-card composition and build-button redesign are deliberately left for UI-03/UI-04; this does not claim all their content fits simultaneously. Debug is narrow on the smallest phone and has a scrollable selector/report.

These are Chromium desktop and emulated touch checks, not physical iOS/Android or RUN host lifecycle verification. Nonzero hardware safe-area insets were not emulated. This pass verifies tutorial entry/placement and saved emergency continuation, not a fresh end-to-end replay of every tutorial expansion/control/city-link stage. Those integrated checks remain part of UI-05. No player acceptance or publication is claimed.
