# First modular mission and diagnostic slice

Implemented locally, September 9, 2026. This supersedes the roundtable's not-started label for the foundation only, not its future occupancy/balance proposals.

- `src/game/cityRules.ts`: first tuning surface for mission targets/rewards and stopped-vehicle threshold. Existing defaults preserved. IDs, dependency graph and outcome evaluators live in cityMissions.ts, independent of UI. Update values then run `nix develop -c npm test` and `nix develop -c npm run build`. Other economy/vehicle constants are not yet centralized; changing capacities also needs save migration review. Earned completions/claims remain permanent; reward edits affect unclaimed awards only.
- `cityMissions.ts`: access, flow, capacity and growth patterns, recommended dependencies (foresight still counts), all-current-household shopping/access outcome, diagnostic links. Existing growth level/land permits reused; no XP currency. Completion requires actual visits and both-direction access, not proof of permanently queue-free throughput. Old completions stay earned. This is the mission foundation, not a full handcrafted campaign.
- `cityDiagnostics.ts`: read-only route/visitor-capacity/wait observations. `DiagnosticViews.tsx` controls map presentation independently of construction and pause. The renderer highlights stopped cars, household access and parked/inbound capacity. Accessible text explains colors and can focus an affected home. No permanent route-history analytics or comparison dashboards added.
- `cityExternal.ts`: confirmed tutorial exit automatically selects the useful network and reaches a map edge across vacant tiles, without overwriting lots or charging funds. Added roads record zero payment. No available safe route means persisted consent and retry when access changes, never a reset. Model retries before constructing its traffic index. H completion, early Skip and title Skip expose confirmation. Existing manual API remains compatible, but the UI no longer requires selecting coordinates.
- `docs/artwork/park/claude-candidate.svg`: actual Claude Code authored editable park sprite candidate from a text-only brief. PNG preview is rendered SVG, not image generation. Current park remains unchanged until user selection; no gameplay alterations.

Validation:199 simulation tests pass, including capacity diagnostics/no mutations, mission receipts/learning, automatic corridor creation, pending consent/reload/no overwrites and real outside visits. Production TypeScript/build pass. Browser checks at320,390,1440 widths switch all views, verify selected state/no horizontal overflow and confirm/cancel tutorial exit; no page errors. Park preview rendered and visually inspected. Gameplay fun and new artwork acceptance remain user judgments.

Limitations: diagnostics update with the existing half-second report and show current observations, not predicted routing capacity. A full visitor count alone is normal utilization; a capacity issue is called out only for relevant waiting household demand. Mission flow labels do not claim the engine measures stable neighborhood throughput or completed return history; further measured puzzle work stays in the backlog. Saved-city data is preserved.
