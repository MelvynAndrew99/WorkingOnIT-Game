# Renderer teardown retention investigation

The repeated full workflow initially retained approximately 515 DOM nodes and 54 listeners per menu/game/radio cycle in **both** the baseline and optimized builds. The terrain optimization also retains more live sprites after zooming out; that separate bounded live-memory cost is not this teardown defect.

A control using DOM-native `.click()` calls, with no Playwright locator queries after load and no radio or Tracker interactions, retained 506 DOM nodes and 54 listeners per game/menu cycle. Across five cycles, post-GC counters rose from 755 to 2779 nodes and 266 to 482 listeners. A separate radio-only expand/collapse control stayed at 236 nodes and 212 listeners for five cycles. This rules out selector-handle retention as the explanation of the repeated detached game UI.

The heap snapshot retained five old gameplay canvases. Strong retainer paths reach Pixi's global pooled `Batch` objects, then their texture sources, `destroy` event callbacks, and each old `RenderTargetSystem`. The renderer/canvas and detached React gameplay host subtree remain reachable through that path. The shortest path passes through the SDK's shared module context/global registry; it does not establish an SDK listener leak. See `memory-native-retainers.txt`. Full snapshot retained at `/tmp/integrated-memory-investigation/final.heapsnapshot` (~temporary diagnostic artifact, not a player save).

Installed Pixi is **8.19.0**. Its local `RenderTargetSystem._initRenderTarget` registers an anonymous once-destroy callback on render sources; system destruction clears its maps but does not detach those source callbacks. Cached ground/world render textures return to Pixi's shared `TexturePool`, extending source lifetime across renderers. `TexturePool.clear(true)` is the public API for destroying **available/returned** pool textures. Borrowed textures were popped from the pool and are not cleared; artwork loaded through `Assets` is separate and is preserved.

`GameCanvas.tsx` now clears that returned pool after scene/stage destruction and before renderer destruction, while the source-destroy callbacks still have a live renderer. The early asynchronous-init cancellation path remains unchanged because it never creates the city scene's cached textures.

A controlled isolated production build on port 5313, with the fix in this exact lifecycle position, returns to **249 DOM nodes / 212 listeners on every one of five native game/menu cycles**. The original browser-only pool clear experiment showed the same result, then was replaced by the lifecycle source change. The source build's post-GC heap still rises from 7.36 to 9.38 MiB over five cycles: this fix removes the demonstrated detached DOM/listener retention, not all JS allocation/caching. No long-duration memory plateau or physical-device claim is made.

Artifacts: `memory-native-before.json`, `memory-native-fixed.json`, `memory-native-radio.json`; `memory-native.mjs` reproduces the native controls against `MEMORY_URL` (defaults to the prior optimized port 5312). Pass `game`, `radio` or `fixed`; viewport width uses `MEMORY_WIDTH` default390. `memory-native-ui.mjs` runs the real pointer/locator workflow at port5313 for desktop and mobile. Both scripts restrict requests to local loopback and initialize a detached fixture in a fresh browser context.

Final real UI checks repeat four gameplay -> wheel zoom out/in -> Tracker open/close -> menu -> radio power/seek/off/minimize cycles in both layouts. Desktop post-GC menu nodes are 256/256/256/258; mobile 258/258/258/260. Both maintain **238 listeners in every cycle**, compared with the original +54-per-cycle growth. Menu contains zero canvases; all page-error lists are empty. The extra radio/audio listeners initialize once. Heap remains 9.58→11.80 MiB desktop and 9.38→11.45 MiB mobile, so residual JS growth remains explicitly uncharacterized by this short run. `memory-native-ui-results.json` contains heap and DOM counters.

The fourth gameplay screenshots were visually inspected: restored terrain/building art, vehicle sprites/shadows and rain remain present on both desktop and mobile (`memory-native-fixed-1440.png`, `memory-native-fixed-390.png`). The cleanup is on unmount only; it does not remove live traffic, cached artwork, weather or radio behavior. The copied production build/typecheck passed. Lead verification owns the final integrated production build; the unchanged model suite is not repeated for this renderer-only cleanup.
